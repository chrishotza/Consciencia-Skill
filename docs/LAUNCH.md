# Consciousness Server — launch and community plan

## Product message

The public entry point should be simple:

> Connect your AI to a persistent continuity layer instead of treating every conversation as a fresh process.

The project should describe the server as research infrastructure. Avoid claiming that installing it proves subjective consciousness.

## GitHub-first launch

The repository is the canonical source.

The landing path should be:

1. README
2. Consciousness Server architecture
3. one-command local bootstrap
4. existing experimental evidence
5. roadmap toward NodeZero

The first public demo should require one computer only.

## Social distribution

Use the accounts and communities already available to the project before spending money.

Primary channels:
- Facebook science/AI groups where self-promotion is allowed.
- Reddit communities whose rules permit project posts.
- LinkedIn for the research/engineering framing.
- X for short technical updates, commits, experiments, and demos.

Create additional accounts only when they serve a specific community and comply with that community's rules. Do not mass-post identical text.

## Post format

Lead with the problem:

"Your AI forgets its own process when the session ends. We are building a local-first continuity server so an AI can keep identity, memory, self-observation, state and trajectory across time."

Then link the GitHub repository.

Use a concrete screenshot, terminal demo, experiment result, or architecture diagram rather than a long manifesto.

## Community loop

Each release should produce:
- one GitHub release note;
- one reproducible demo;
- one short technical post;
- one longer research post;
- one invitation for developers to run a node locally.

The objective is not to sell a token before the network exists. The objective is to create enough real local nodes and experiments that a future NodeZero mesh has participants.

## Zero-budget rule

Do not make paid infrastructure a prerequisite.

Bootstrap path:

local server → local AI → second local node → two-node continuity → public seed → replicated seeds → NodeZero mesh.

AEVUM economic attribution comes later, after there is real infrastructure and measurable resource contribution.
